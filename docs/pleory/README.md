읽는 순서: README → 기능명세 §0~§2 → prototype.html 한 바퀴 → 기능명세 §3~§9.

**1일차 오전에 가장 먼저 볼 것 (명세 §2 F0, §9):** 앱에 `distractionOptimized` 선언이 없으면 Pleos 정책상 주행 중(기어 D) 앱이 뜨지 않는다. 이게 안 되면 나머지가 의미 없다.

prototype.html 안의 STT·TTS·LLM은 전부 가짜(자바스크립트)다. 실제 앱에서는 SpeechToText SDK, TextToSpeech SDK, 외부 LLM API로 교체. 주행 중 "적어뒀어"는 TTS이고 화면엔 아무것도 뜨지 않으므로, 프로토타입에서는 오른쪽 콘솔 로그에 🔊로만 표시된다. 가짜 LLM이 문장을 나누는 방식(쉼표·'그리고'·'근데' 분리, 키워드로 유형 추정)은 §4-1 계약의 기대 동작을 보여주기 위한 것이고 실제 분류는 LLM이 한다. 15초 요약은 명세 §4-2대로 LLM 없이 로컬 규칙으로 조립한다.

2일 데모에서 날씨·장소 라벨은 fixture(고정값·좌표→라벨 표)다. README(앱 저장소)에도 그렇게 적는다.

기획서에 없는 기능은 넣지 않았고, 기획서와 어긋나는 부분을 찾으면 기획서가 기준이다.
