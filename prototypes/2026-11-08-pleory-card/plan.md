# Pleory — '오늘의 나' 카드(S1) · 주행 화면(S0) 시안

- 슬러그 `2026-11-08-pleory-card` · Kotlin 패키지 `pleorycard`
- 코드 `app/src/debug/java/ai/pleos/hello/proto/pleorycard/` (debug 전용)
- 0단계는 PRD(`docs/pleory/Pleory_기능명세_v2.md`)로 갈음했다. 사용자가 2026-11-08 병렬 진행을 지시함.

## 1. 배경

- Pleory는 운전 중 떠오르는 대로 말하면 AI가 정리하고, 차가 시간·장소·주행 맥락을 붙여 통근마다 한 편씩 쌓아 주는 Pleos 드라이브 저널이다. (PRD §0)
- 1차 범위는 S1 퇴근길 end-to-end다. 2일 안에 에뮬레이터에서 끝까지 돌리는 것이 목표다. (PRD §9)
- 카드 시안 `card_mock.png`는 3840×1440(2.67:1)으로 그려졌다. 11/8 에뮬레이터 실측 결과 앱이 쓰는 영역은 **1682×1210dp(1.39:1)**였다. 구성 요소는 그대로 쓰되 배치를 다시 짜야 한다. (PRD §5)

## 2. 문제 정의

- 누가: 퇴근길 운전자. 주행 중에는 말만 하고, 도착해 기어 P에 놓은 뒤 화면을 본다.
- 어떤 상황에서:
  - S0: 주행 중. 화면은 버튼 1개와 고정 상태 텍스트뿐이고, 상태 변화는 버튼의 "듣는 중"만 허용된다(원칙 1·2).
  - S1: 목적지에 도착해 기어 P. 차에서 내리기 전 짧은 시간 동안 본다.
- 무엇이 막히나: 승인된 카드 구성을 앱 영역 비율에 그대로 옮기면 경로 영역이 너무 좁아지고 제목 블록이 들어갈 자리가 없다. 어떤 배치가 "한눈에 오늘을 돌아보기"(통계 → 감정 흐름 → 항목)를 가장 잘 받쳐 주는지 아직 정하지 않았다.
- 근거: PRD §5 재배치 지침과 실측 앱 영역. 사용자 데이터는 없다(가설).

## 3. 범위

- In: S1 카드 정적 배치 3안, S0 주행 화면 2안(기본 상태와 듣는 중 상태)
- Out: 요약 재생 중 자막·건너뛰기, 항목 편집 시트, QR 모달, S2·S3, 세로(분할) 레이아웃, 실제 데이터 연동, 애니메이션

## 4. User Stories & AC

```
US-1: 도착 후 오늘 기록 한눈에 보기
  As 퇴근길 운전자, I want 기어 P 직후 카드에서 시간·거리·한마디 수와 감정 흐름을 바로 보고,
  so that 오늘 통근이 어땠는지 몇 초 안에 떠올린다.
  AC:
    - Given 기어 P + 도착 판정, When 카드가 뜨면, Then 제목·통계 4·감정 흐름 바·항목 목록이 스크롤 없이 첫 화면에 보인다(항목 3개 기준)
    - Given 항목이 많을 때, When 목록을 스크롤해도, Then 하단 버튼 줄은 고정이다
US-2: 주행 중 한마디 남기기
  As 운전자, I want 화면의 큰 버튼 1탭으로 말하고,
  so that 시선을 거의 옮기지 않고 기록한다.
  AC:
    - Given 주행 중, When 버튼을 탭하면, Then 버튼만 "듣는 중"으로 바뀌고 나머지 화면은 그대로다
```

검토 메모: 빈 세션(항목 0개)과 LLM 실패(유형 태그 "원문")는 R1에서 그리지 않았다. 수렴 뒤 확정안에 상태를 추가한다.

## 5. 차량 데이터

전부 가짜 데이터(상수)다. PRD §8 시연 값: 51분 · 23km · 한마디 2 · 항목 3, 18:57 올림픽대로(정체 23분), 19:08 한강대교. 경로·핀은 Canvas로 그린 폴리라인이고 지도는 없다.

## 6. 핵심 사용자 가치

주행 중에는 말 한마디로 기록만 하고, 도착하면 그 기록이 맥락과 함께 한 장으로 정리돼 있다.

## 7. 인터랙션 흐름

S0(버튼 1탭 → 듣는 중 → 원래대로, TTS "적어뒀어") → 도착 + 기어 P → S1 카드 → 15초 요약 / 수정 / 폰에서 열기 / 이번 주 / 설정

**찾지 못한 것**: 버튼·터치 타깃의 dp 수치. Basic button 페이지에는 Large/Medium/Small 그림만 있고 숫자가 없다. 그래서 AAOS 운전자 주의 분산 가이드의 **76dp**를 하한으로 두고 80dp를 썼다(가정 유지).

**PRD 가정값을 바꾼 것**

- 본문 최소 24sp(가정) → **Body M 28**(항목 문장), **Body S 26**(메타 줄, 버튼), Label M 24 / Label S 20(보조 라벨·메타). 20 미만은 쓰지 않는다.
- 제목 "퇴근길 51분" → **Headline S 48**, 통계 숫자 → **Title L 40**, S0 상태 텍스트 → Title S 32(A) / Title L 40(B)
- 바깥 여백 32dp(가정) → **40dp**. 앱 영역 가장자리와 시스템 패널 사이 간격을 실측 화면에서 보고 늘렸다.
- 터치 타깃 76dp(가정) → **80dp**. 항목 행은 96dp 이상이다.

**그 외**

- 색은 PRD §3 그대로. 보조 글자 `#9AA8BC`(BG 대비 약 7.6:1), 면 `#141F33`, 칩 `#1D2A42`. 장식용 그라데이션·그림자·블러는 쓰지 않았다.
- 한글 줄바꿈은 API 33+ `LINE_BREAK_WORD_STYLE_PHRASE`(keep-all에 해당)를 쓴다. 좁은 칸은 의미 단위로 미리 끊는다.
- 경로 선은 단색(slate)이다. 감정은 핀 색과 흐름 바로만 표시한다. 시안의 그라데이션 선은 "감정이 다음 한마디까지 이어진다"는 근거 없는 해석을 만든다.
- 폰트는 에뮬레이터 기본 산세리프(Noto Sans CJK)를 썼다. Asta Sans 번들 여부는 미정이다.

## 9. 미정 / 논의 필요

- 버튼 크기 Pleos 공식 수치(Basic button의 Large 높이). Figma 에셋(Design Resources Download)에서 확인 필요
- 세로(분할) 레이아웃: 앱 2개가 뜰 때의 실제 폭 실측(PRD §5 "P1에서 실측")
- 폰트 Asta Sans를 앱에 넣을지
- 감정을 색만으로 구분하는 문제(접근성): 흐름 바 옆 화살표 외에 항목에도 감정 텍스트를 붙일지
- S0 버튼 좌/우 기본값(설정 S3의 "버튼 위치" 기본)

## 10. Round 2 — 시각·문구 톤 발산 (2026-11-08)

- 계기: 사용자 "지금 UI가 기획자 시안을 그대로 옮겨서 AI가 만든 것 같다". 0단계(배경·문제)는 위 1·2절 그대로 유효하고, R2는 **정보 구조는 R1에서 정한 대로 두고 색·위계·배치·문구 톤만** 다시 발산한다. 데이터·로직은 바꾸지 않는다.
- 범위 In: S0(기본·듣는 중), S1(가로 2열·세로 1열, 요약 재생 중, 한마디 0개), S3 설정(삭제 확인 포함), 동의 화면. Out: 편집 시트, QR 모달, S2, 주간(라이트) 모드.
- 기준: Pleos 수치(본문 18px 이상, 대비 4.5:1, 중요 글자 약 5mm, 0.25초 응답, 주행 중 움직임 없음, 시스템 글꼴, 가로·세로 둘 다, 큰 터치 영역)와 Jakub Krehel 의 interface 체크리스트(동심 모서리, 구조용 선만, 고정폭 숫자, 색 하나에 뜻 하나, 화면당 채운 버튼 하나, 정직한 문구).
- 세 방향: **A 일지**(따뜻한 흑연, 글로 읽는 카드), **B 계기**(무채색 + 청록 하나, 시간축 감정 차트), **C 한마디**(말한 그대로가 주인공, 경로가 창 끝까지).
- 진단·자가 점검·추천은 `rounds/r2/round.md`. 코드는 `proto/pleorycard/r2/`.
- 9절 미정 중 "감정을 색만으로 구분하는 문제"는 R2 세 안 모두 글리프 + 낱말 + 색으로 풀었다. "S0 듣는 중이 기본보다 덜 눈에 띈다"(R1 메모)도 세 안 모두 듣는 중을 더 밝게 바꿨다.
